Data Integration Challenge

Overcoming Garmin API limitations

Initial Approach: Webhook + Scheduled Polling

Real-time webhooks triggered by Garmin when activities completed. Scheduled Lambda functions polled for updates every 6 hours. Expected workflow: seamless, automatic data sync.

The Problem

  • ▸ Webhook delivery was unreliable — some activities never triggered
  • ▸ Historical data gaps — Garmin API didn't return complete activity history
  • ▸ Rate limiting on polling requests caused delays in data sync
  • ▸ Data consistency issues — some fields missing or incomplete

Our Solution

Manual Garmin data exports combined with Lambda batch processing. Users export full activity history from Garmin Connect, upload to system, Lambda functions parse and normalize the data. This approach guarantees data completeness and consistency while working around API limitations.

Lambda Processing Pipeline

4 specialized functions for data transformation

Function 1: Parser

  • Reads Garmin export files (CSV/JSON)
  • Validates data integrity
  • Handles format variations
  • Logs parsing errors

Function 2: Transformer

  • Normalizes date/time formats
  • Unit conversions (mi to km, etc.)
  • Cleans missing values
  • Enriches metadata

Function 3: Metrics Calculator

  • Computes pace, HR zones, effort
  • Calculates weekly/monthly aggregates
  • Training load scoring
  • Recovery time estimation

Function 4: Sleep Correlation

  • Links activities to sleep data
  • Calculates recovery scores
  • Identifies patterns & trends
  • Prepares Claude AI analysis

DynamoDB Time-Series Design

50M+ rows optimized for performance

Primary Key Design

Partition Key (PK):
activity#USER_ID
Sort Key (SK):
TIMESTAMP#ACTIVITY_ID

Attributes Stored

Activity Data
type, distance, duration, pace, elevation
Heart Data
hr_avg, hr_max, hr_zone, vo2_max
Recovery Data
recovery_time, training_load, stress_level
Sleep Correlation
sleep_quality, recovery_score, impact

Query Patterns

  • ▸ Activities by user in date range (SK range query)
  • ▸ Last 30 days of activities (efficient scanning with TTL)
  • ▸ Sleep-activity correlation lookup (index query)

Challenges & Solutions

What we learned along the way

API Reliability

Challenge: Garmin webhooks were unreliable. Solution: Switched to manual exports + Lambda batch processing for guaranteed data completeness.

Data Quality

Challenge: Missing/incomplete fields in raw data. Solution: Built validation layer in Lambda with error logging and manual review workflows.

Storage Scaling

Challenge: 50M rows needed efficient queries. Solution: Optimized DynamoDB schema with time-series partitioning and GSIs for fast lookups.
