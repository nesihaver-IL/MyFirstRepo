## Overview

This guide will walk you through creating an IAM user with appropriate permissions to:
- Access AWS Bedrock models
- Create and manage Bedrock Agents
- Create and manage Knowledge Bases
- Invoke Lambda functions (for action groups)
- Access S3 buckets (for knowledge base documents)
- View CloudWatch logs and metrics

**Estimated Time:** 15-30 minutes

---

## Prerequisites

Before starting, ensure you have:
- [ ] AWS Account with administrator access (or IAM permissions to create users)
- [ ] Access to AWS Console
- [ ] Understanding of your region (e.g., us-east-1, us-west-2)
- [ ] AWS CLI installed on your local machine (optional but recommended)

---

## Step 1: Access AWS IAM Console

### 1.1 Log into AWS Console

1. Open your web browser
2. Navigate to: https://console.aws.amazon.com/
3. Sign in with your root account or administrator credentials
4. Verify you're in the correct region (top-right corner)
   - Recommended regions for Bedrock: **us-east-1** or **us-west-2**

### 1.2 Navigate to IAM

1. In the AWS Console search bar (top), type: **IAM**
2. Click on **IAM** (Identity and Access Management)
3. You should now see the IAM Dashboard

**Screenshot checkpoint:** You should see "IAM Dashboard" with options like Users, Groups, Roles, and Policies

---

## Step 2: Create IAM User

### 2.1 Start User Creation

1. In the left sidebar, click on **Users**
2. Click the **Create user** button (orange button, top-right)
3. You'll be taken to "Specify user details" page

### 2.2 Configure User Details

**Step 1 of 3: Specify user details**

1. **User name:** Enter a descriptive name
   - Example: `bedrock-developer`
   - Example: `bedrock-agent-admin`
   - Example: `your-name-bedrock`

2. **Provide user access to the AWS Management Console (optional)**
   - Check this box if you want this user to access the AWS Console
   - Select: **I want to create an IAM user**

3. **Console password**
   - Choose: **Custom password**
   - Enter a strong password (minimum 8 characters)
   - Alternatively: **Autogenerated password** (system creates one)

4. **Require password reset**
   - Recommended: Check **"Users must create a new password at next sign-in"**
   - This enforces password change on first login

5. Click **Next** button

**What you've done:** Created the basic user account with console access

---

## Step 3: Attach Bedrock Permissions

### 3.1 Choose Permission Assignment Method

**Step 2 of 3: Set permissions**

You have three options:
- **Option A:** Add user to group (recommended for multiple users)
- **Option B:** Copy permissions from existing user
- **Option C:** Attach policies directly (we'll use this for simplicity)

Select: **Attach policies directly**

### 3.2 Attach AWS Managed Policies

In the search box under "Permissions policies", search and select the following policies:

#### Required Policies for Bedrock Operations:

1. **AmazonBedrockFullAccess**
   - Search: `AmazonBedrockFullAccess`
   - Check the box next to it
   - **What it does:** Full access to Bedrock models, agents, and knowledge bases

2. **IAMFullAccess** (for creating service roles)
   - Search: `IAMFullAccess`
   - Check the box
   - **What it does:** Allows creating IAM roles for Bedrock agents
   - **Alternative (more restrictive):** Create a custom policy (see Section 10)

3. **AWSLambda_FullAccess**
   - Search: `AWSLambda_FullAccess`
   - Check the box
   - **What it does:** Create and manage Lambda functions for action groups

4. **AmazonS3FullAccess**
   - Search: `AmazonS3FullAccess`
   - Check the box
   - **What it does:** Upload documents to S3 for knowledge bases
   - **Alternative (more restrictive):** Use `AmazonS3ReadOnlyAccess` + custom bucket policy

5. **CloudWatchLogsFullAccess**
   - Search: `CloudWatchLogsFullAccess`
   - Check the box
   - **What it does:** View logs for debugging agents

6. **CloudWatchFullAccess** (optional)
   - Search: `CloudWatchFullAccess`
   - **What it does:** Monitor agent performance metrics

### 3.3 Review Selected Policies

You should have selected **5-6 policies** (depending on your needs):
- ✓ AmazonBedrockFullAccess
- ✓ IAMFullAccess
- ✓ AWSLambda_FullAccess
- ✓ AmazonS3FullAccess
- ✓ CloudWatchLogsFullAccess
- ✓ CloudWatchFullAccess (optional)

Click **Next** button

**What you've done:** Granted comprehensive Bedrock permissions to the user

## Step 4: Create Access Keys

### 4.1 Review and Create User

**Step 3 of 3: Review and create**

1. Review all settings:
   - User name
   - Console access
   - Permissions (should list all 5-6 policies)

2. **Optional:** Add tags
   - Key: `Project`, Value: `BedrockAgent`
   - Key: `Environment`, Value: `Development`

3. Click **Create user** button

### 4.2 Save Console Access Information

**Important:** You'll see a success message with:
- Console sign-in URL
- Username
- Password (if autogenerated)

**Action Required:**
1. Click **Download .csv** button (save this securely!)
2. Save the console sign-in URL
3. Copy the password if autogenerated

### 4.3 Generate Access Keys for CLI/SDK

Now we need to create programmatic access keys:

1. After creating the user, you're on the Users list page
2. Click on your newly created user name (e.g., `bedrock-developer`)
3. Click on the **Security credentials** tab
4. Scroll down to **Access keys** section
5. Click **Create access key** button

### 4.4 Select Use Case

You'll see "Access key best practices & alternatives":

1. Select use case: **Command Line Interface (CLI)**
2. Check the box: **"I understand the above recommendation..."**
3. Click **Next** button

### 4.5 Set Description Tag

1. **Description tag value (optional):** Enter a description
   - Example: `Bedrock development access`
   - Example: `Local CLI access for agent development`

2. Click **Create access key** button

### 4.6 Retrieve Access Keys

**CRITICAL:** This is your ONLY chance to see the Secret Access Key!

You'll see:
- **Access key:** (starts with AKIA...)
- **Secret access key:** (long random string)

**Action Required:**
1. Click **Download .csv file** button
2. Save this file in a secure location
3. **NEVER commit this to Git or share publicly**
4. Copy both keys (you'll need them in the next step)

Click **Done** button

**What you've done:** Created programmatic access credentials for AWS CLI/SDK

## Step 5: Configure AWS CLI

### 5.1 Verify AWS CLI Installation

Open your terminal (Command Prompt, PowerShell, or Terminal):

```bash
aws --version
```

**Expected output:**
```
aws-cli/2.x.x Python/3.x.x ...
```

If not installed, install from: https://aws.amazon.com/cli/

### 5.2 Configure AWS CLI with User Credentials

Run the configuration command:

```bash
aws configure
```

You'll be prompted for:

```
AWS Access Key ID [None]: AKIA...YOUR_ACCESS_KEY
AWS Secret Access Key [None]: YOUR_SECRET_ACCESS_KEY
Default region name [None]: us-east-1
Default output format [None]: json
```

**Important:**
- Use the access keys from Step 4.6
- Region should be where Bedrock is available (us-east-1, us-west-2, etc.)
- Output format: `json` is recommended

### 5.3 Create Named Profile (Optional)

If you want to keep multiple AWS profiles:

```bash
aws configure --profile bedrock-dev
```

Then use it with:
```bash
aws bedrock list-foundation-models --region us-east-1 --profile bedrock-dev
```

### 5.4 Verify Configuration

Check your configuration:

```bash
# View current configuration
aws configure list

# Test credentials
aws sts get-caller-identity
```

**Expected output:**
```json
{
    "UserId": "AIDA...",
    "Account": "123456789012",
    "Arn": "arn:aws:iam::123456789012:user/bedrock-developer"
}
```

**What you've done:** Configured local environment to use the IAM user credentials

## Step 6: Verify Access

### 6.1 Test Bedrock Access

Test that you can access Bedrock:

```bash
# List available Bedrock models
aws bedrock list-foundation-models --region us-east-1
```

**Expected output:** JSON list of available models

If you get an error, proceed to Section 6.4

### 6.2 Test Model Access

Check if you have access to specific models:

```bash
# List models with access status
aws bedrock list-foundation-models \
  --region us-east-1 \
  --query 'modelSummaries[?contains(modelId, `anthropic.claude`)].{ModelId:modelId, ModelName:modelName}' \
  --output table
```

### 6.3 Request Model Access (If Needed)

If you don't have model access yet:

1. Go to AWS Console → Bedrock
2. Click **Model access** in left sidebar
3. Click **Modify model access** button
4. Select models you need:
   - **Anthropic Claude 3 Sonnet** (recommended)
   - **Anthropic Claude 3 Haiku**
   - **Amazon Titan models**
5. Review and submit access request
6. Wait for approval (usually instant)

### 6.4 Troubleshooting Access Issues

**Problem:** "UnauthorizedOperation" or "AccessDeniedException"

**Solutions:**

1. **Check if Bedrock is available in your region:**
   ```bash
   aws bedrock list-foundation-models --region us-west-2
   ```

2. **Verify IAM permissions:**
   - Go to IAM Console → Users → Your user
   - Check that policies are attached
   - Look for "AmazonBedrockFullAccess"

3. **Check if you're using the correct credentials:**
   ```bash
   aws sts get-caller-identity
   ```
   Verify the returned user ARN matches your IAM user

4. **Try with explicit region:**
   ```bash
   aws bedrock list-foundation-models --region us-east-1
   ```

### 6.5 Test Complete Workflow

Try a complete test:

```bash
# 1. List models
aws bedrock list-foundation-models --region us-east-1 --query 'modelSummaries[0].modelId' --output text

# 2. List S3 buckets
aws s3 ls

# 3. List Lambda functions
aws lambda list-functions --region us-east-1

# 4. Check CloudWatch logs
aws logs describe-log-groups --region us-east-1 --max-items 5
```

If all commands work without errors, your IAM user is properly configured!

**What you've done:** Verified that your IAM user has all necessary permissions

## Security Best Practices

### 7.1 Access Key Security

- [ ] **Never** commit access keys to Git repositories
- [ ] **Never** share access keys in plain text
- [ ] Store keys in secure password manager
- [ ] Rotate keys every 90 days
- [ ] Delete unused access keys

### 7.2 Enable MFA (Multi-Factor Authentication)

**Highly Recommended for production:**

1. Go to IAM → Users → Your user
2. Click **Security credentials** tab
3. Scroll to **Multi-factor authentication (MFA)**
4. Click **Assign MFA device**
5. Follow the setup wizard

### 7.3 Implement Least Privilege

Instead of `*FullAccess` policies, create custom policies with only needed permissions:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "bedrock:InvokeModel",
        "bedrock:ListFoundationModels",
        "bedrock:GetFoundationModel"
      ],
      "Resource": "*"
    }
  ]
}
```

### 7.4 Monitor User Activity

- Enable CloudTrail logging
- Review CloudWatch logs regularly
- Set up alerts for suspicious activity

### 7.5 Use IAM Roles Instead of Users (When Possible)

For applications running on AWS (EC2, Lambda, ECS):
- Use IAM Roles instead of access keys
- Roles automatically rotate credentials
- More secure than long-lived access keys

## Custom Policy Examples

### 8.1 Minimal Bedrock Agent Developer Policy

If you want more restrictive permissions:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "BedrockModelAccess",
      "Effect": "Allow",
      "Action": [
        "bedrock:InvokeModel",
        "bedrock:InvokeModelWithResponseStream",
        "bedrock:ListFoundationModels",
        "bedrock:GetFoundationModel"
      ],
      "Resource": "*"
    },
    {
      "Sid": "BedrockAgentManagement",
      "Effect": "Allow",
      "Action": [
        "bedrock:CreateAgent",
        "bedrock:UpdateAgent",
        "bedrock:GetAgent",
        "bedrock:ListAgents",
        "bedrock:DeleteAgent",
        "bedrock:PrepareAgent",
        "bedrock:CreateAgentAlias",
        "bedrock:UpdateAgentAlias",
        "bedrock:GetAgentAlias",
        "bedrock:ListAgentAliases",
        "bedrock:DeleteAgentAlias",
        "bedrock:CreateAgentActionGroup",
        "bedrock:UpdateAgentActionGroup",
        "bedrock:GetAgentActionGroup",
        "bedrock:ListAgentActionGroups",
        "bedrock:DeleteAgentActionGroup"
      ],
      "Resource": "*"
    },
    {
      "Sid": "BedrockKnowledgeBaseManagement",
      "Effect": "Allow",
      "Action": [
        "bedrock:CreateKnowledgeBase",
        "bedrock:UpdateKnowledgeBase",
        "bedrock:GetKnowledgeBase",
        "bedrock:ListKnowledgeBases",
        "bedrock:DeleteKnowledgeBase",
        "bedrock:AssociateAgentKnowledgeBase",
        "bedrock:DisassociateAgentKnowledgeBase"
      ],
      "Resource": "*"
    },
    {
      "Sid": "S3KnowledgeBaseBuckets",
      "Effect": "Allow",
      "Action": [
        "s3:ListBucket",
        "s3:GetObject",
        "s3:PutObject",
        "s3:DeleteObject"
      ],
      "Resource": [
        "arn:aws:s3:::*bedrock*",
        "arn:aws:s3:::*bedrock*/*"
      ]
    },
    {
      "Sid": "LambdaForActionGroups",
      "Effect": "Allow",
      "Action": [
        "lambda:CreateFunction",
        "lambda:UpdateFunctionCode",
        "lambda:UpdateFunctionConfiguration",
        "lambda:GetFunction",
        "lambda:ListFunctions",
        "lambda:DeleteFunction",
        "lambda:InvokeFunction",
        "lambda:AddPermission",
        "lambda:RemovePermission"
      ],
      "Resource": "arn:aws:lambda:*:*:function:*bedrock*"
    },
    {
      "Sid": "IAMPassRoleForBedrock",
      "Effect": "Allow",
      "Action": [
        "iam:GetRole",
        "iam:PassRole"
      ],
      "Resource": "arn:aws:iam::*:role/*Bedrock*",
      "Condition": {
        "StringEquals": {
          "iam:PassedToService": "bedrock.amazonaws.com"
        }
      }
    },
    {
      "Sid": "CloudWatchLogs",
      "Effect": "Allow",
      "Action": [
        "logs:CreateLogGroup",
        "logs:CreateLogStream",
        "logs:PutLogEvents",
        "logs:DescribeLogGroups",
        "logs:DescribeLogStreams"
      ],
      "Resource": "arn:aws:logs:*:*:log-group:/aws/bedrock/*"
    }
  ]
}
```

### 8.2 Read-Only Bedrock Policy

For monitoring or auditing:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "bedrock:Get*",
        "bedrock:List*",
        "bedrock:Describe*"
      ],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "logs:Get*",
        "logs:List*",
        "logs:Describe*",
        "logs:FilterLogEvents"
      ],
      "Resource": "arn:aws:logs:*:*:log-group:/aws/bedrock/*"
    }
  ]
}
```

### 8.3 How to Create Custom Policy

1. Go to IAM → Policies
2. Click **Create policy**
3. Click **JSON** tab
4. Paste your custom policy
5. Click **Next**
6. Name: `BedrockDeveloperCustomPolicy`
7. Description: `Custom policy for Bedrock development`
8. Click **Create policy**
9. Go back to your user and attach this policy

## Quick Reference Commands

### IAM User Management
```bash
# List IAM users
aws iam list-users

# Get user details
aws iam get-user --user-name bedrock-developer

# List user policies
aws iam list-attached-user-policies --user-name bedrock-developer

# List access keys
aws iam list-access-keys --user-name bedrock-developer
```

### Bedrock Operations
```bash
# List models
aws bedrock list-foundation-models --region us-east-1

# List agents
aws bedrock-agent list-agents --region us-east-1

# List knowledge bases
aws bedrock-agent list-knowledge-bases --region us-east-1

aws bedrock-runtime invoke-model \
  --model-id anthropic.claude-3-sonnet-20240229-v1:0 \
```

```bash
# Create new access key
aws iam create-access-key --user-name bedrock-developer

# Delete old access key
aws iam delete-access-key --user-name bedrock-developer --access-key-id AKIA...
```

## Troubleshooting Common Issues

### Issue 1: "Access Denied" when listing models

**Cause:** IAM policy not attached or incorrect region

**Solution:**
```bash
# Verify attached policies
aws iam list-attached-user-policies --user-name bedrock-developer

# Try different region
aws bedrock list-foundation-models --region us-west-2
```

### Issue 2: "Model access not granted"

**Cause:** Need to request model access in Bedrock Console

**Solution:**
1. AWS Console → Bedrock → Model access
2. Request access for needed models
3. Wait for approval (usually instant)

### Issue 3: Cannot create Bedrock agent

**Cause:** Missing IAM PassRole permission

**Solution:** Attach this policy:
```json
{
  "Effect": "Allow",
  "Action": "iam:PassRole",
  "Resource": "*",
  "Condition": {
    "StringEquals": {
      "iam:PassedToService": "bedrock.amazonaws.com"
    }
  }
}
```

### Issue 4: Access keys not working

**Cause:** Keys not properly configured or deactivated

**Solution:**
```bash
# Verify current identity
aws sts get-caller-identity

# Check if using correct profile
aws configure list

# Reconfigure if needed
aws configure
```
