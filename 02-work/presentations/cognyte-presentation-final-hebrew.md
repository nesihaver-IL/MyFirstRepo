## סלייד 5: ניהול פרויקטים - 4 עקרונות זהב

**כותרת**: "ניהול פרויקטים - הדברים שצריך להיות שליטה בהם"

### **4 עקרונות הזהב (Golden Constraints)**:

#### **1️⃣ זמן (TIME)**
```
⏰ השאלות:
  • כמה זמן הפרויקט כולו?
  • כמה זמן כל משימה?
  • מה הדדליינים?
  • מה ה-critical path? (משימות שאי אפשר לתלות)

💡 דוגמה:
  "אנחנו צריכים לסיים עד 31.12"
  - משימה א': 2 שבועות (חשובה מאד)
  - משימה ב': 1 שבוע (יכולה לחכות)
  
⚠️ סכנה:
  אם אדם א' מתעכב ב-2 שבועות → הפרויקט נדחה 2 שבועות!
```

#### **2️⃣ תקציב (BUDGET)**
```
💰 השאלות:
  • כמה כסף יש לנו?
  • כמה עולה כל משימה?
  • מי מחליט על עדיפויות אם אין כסף?
  • מה עושים אם נגמר כסף?

💡 דוגמה:
  תקציב כולל: 100,000 שח
  - משכורות: 60,000
  - כלים: 20,000
  - בדיקות: 15,000
  - חוצצים: 5,000

⚠️ סכנה:
  אם משכורות עולות → צריך לחתוך משקום אחר!
```

#### **3️⃣ משאבים (RESOURCES)**
```
👥 השאלות:
  • כמה אנשים צריכים?
  • מה הכישורים?
  • איזו כלים יש?
  • איך מחלקים עבודה?

🧠 כישורים קריטיים:
  ✓ חיבור בין אנשים (communication)
  ✓ הקצאת משאבים (allocation)
  ✓ הנחיית קבוצות (leadership)
  ✓ האזנה לדעות אחרים (listening)
  ✓ הבנה טכנית וניהולית (both worlds)
  ✓ זיהוי חוזה הרכישה (contract awareness)
  ✓ התאמת תוכנית לרב משתתפים

💡 דוגמה:
  צוות: 5 מתכנתים + 1 מעצב + 1 ממנהל
  ממנהל צריך:
  - לדעת איפה כל אדם חזק
  - להקצות משימות בחוכמה
  - לשמוע כשמישהו אומר "אני לא יכול"
  - להבין גם בקוד וגם בניהול
```

#### **4️⃣ תכולה (SCOPE)**
```
📋 השאלות:
  • מה בדיוק אנחנו בונים?
  • מה לא בונים?
  • מה הדרישות בדיוק?
  • מה אם הלקוח רוצה להוסיף?

⚖️ Scope Creep (הסכנה):
  ❌ בעיה: "אפליקציה קטנה" → הלקוח רוצה 10 דברים נוספים
  → זמן עולה, כסף עולה, אנשים עייפים!
  
  ✅ פתרון: "אם רוצה משהו חדש - זה פרויקט אחר או כסף נוסף"

💡 דוגמה:
  תחילה: "אתר עם עמוד בית וחנות"
  אמצע: "אה, ולא צריך payment ודוחות?"
  סוף: "אה, ולא משחקים וVR?"
  → זמן: 2 חודשים → 6 חודשים
  → כסף: 100K → 300K
```

## סלייד 6: Agile vs Waterfall

```
🏗️ Waterfall (תוכנית מקדימה)
   ├─ הכל מתוכנן בתחילה
   ├─ בנייה ישירה לפי התוכנית
   ├─ בדיקות רק בסוף
   ├─ שינויים = בעיה גדולה
   └─ טוב ל: בנייה (מטוסים, בתים)

📈 Agile (תוכנית גמישה)
   ├─ תוכנית בחלקים קטנים (ספרינטים)
   ├─ בנייה, בדיקה, משוב בכל ספרינט
   ├─ שינויים = קל יותר
   ├─ משוב מהלקוח כל שבועות
   └─ טוב ל: תוכנה וטכנולוגיה
```
